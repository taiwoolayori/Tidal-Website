### Provisioning protocol

1. Confirm the actual mail provider and admin authority. Decide whether each address is an alias, collaborative inbox/group or licensed mailbox.
2. Define authorized recipient or team, retention, reply-from rights, forwarding and private data protections. Foundation correspondence must remain suitably separated.
3. Create and verify each address in the provider console.
4. Send an inbound test from an external domain, reply through the intended authorized identity, and verify correct routing.
5. Record actual verification date, owner and delivery evidence **in a private operations register, not this public repository**.
6. Only after verification switch the website CTA from `info@tidalcrestgroup.com` to its dedicated mailbox.
7. Keep website aliases distinct from the future OFES controlled intake API. Do not claim that mailto creates a tracked case.

No changes to MX, SPF, DKIM, DMARC or mail subscriptions are authorized by this register. No credentials or recipient personal addresses belong in this repository.
